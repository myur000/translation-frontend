# Просмотр настоящих документов

Реализовано 9 октября 2026 года, только во frontend. Backend не изменялся.

## Что видит пользователь

- Выбор PDF или DOCX в «Добавить книгу» сразу открывает настоящий оригинал.
- Запуск перевода использует существующую загрузку документа. Пока задача не
  завершена, правая панель показывает состояние, а не демонстрационные страницы.
- После DONE перевод автоматически скачивается из API и открывается справа.
- PDF: настоящие страницы, их количество, переходы между страницами и выделение
  текста, если текстовый слой присутствует в самом PDF. OCR для сканов не добавлен.
- DOCX: текст, заголовки, списки, таблицы и поддерживаемые встроенные изображения.
  Это непрерывное адаптированное представление, не точная копия Word.
- Масштаб, вертикальная и горизонтальная прокрутка, синхронизация и полноэкранные
  режимы работают с настоящим содержимым. Переключение между оригиналом, переводом
  и обеими панелями не уничтожает данные открытого документа.

## Откуда берутся файлы

Оригинал хранится как File в состоянии текущего пользователя, только в памяти.
Backend сохраняет задачи, но не предоставляет endpoint получения исходного файла.
После обновления страницы история и job_id восстанавливаются, оригинал — нет.
Кнопка «Выбрать исходный файл» позволяет прикрепить файл к существующей книге
для локального просмотра: без POST, повторного перевода и изменения job_id.
Проверяются допустимый формат, соответствие формату задачи и лимит загрузки 20 МБ.
Пользователь должен выбрать именно соответствующий оригинал: API не предоставляет
контрольной суммы для проверки идентичности содержимого.

Готовый перевод получается через существующий download endpoint по job_id, с JWT
и штатным механизмом refresh. Обновление access token не перезагружает открытый
файл. Смена книги, выход и размонтирование отменяют незавершённые запросы.
При 404/410, сетевой ошибке или повреждённом файле показывается понятное состояние;
ошибку получения файла можно повторить кнопкой. HTML/JSON вместо бинарного
документа не принимаются за содержимое книги.

Просмотр и кнопка скачивания пока используют независимые запросы. Общий кэш
двоичных файлов можно добавить позже, если размер документов сделает это важным.

## Архитектура

- `src/hooks/useDocumentAssets.ts`: локальный оригинал, API-файл перевода,
  отмена загрузки, ошибки и повтор.
- `src/hooks/useDocumentView.ts`: загрузка движка по формату, разбор файла,
  освобождение PDF worker. Живёт над условно отображаемыми панелями.
- `src/viewer/pdfEngine.ts`: PDF.js, метаданные и количество страниц.
- `src/viewer/docxEngine.ts`: Mammoth и очистка результата через DOMPurify.
- `src/viewer/readBlob.ts`: чтение Blob/File с отменой.
- `PdfPages.tsx`: страницы PDF, canvas и выделяемый текстовый слой.
  Страницы вблизи видимой области отрисовываются через IntersectionObserver;
  остальные сохраняют геометрию, но не удерживают canvas.
- `DocumentPages.tsx`: выбор PDF/DOCX-представления.
- `DocumentPreview.tsx`: общая рамка, состояния, масштаб, прокрутка и навигация.
- `plugins/pdfAssets.ts`: локальные ресурсы PDF.js для dev и production.

Рабочая область сохраняет отдельно масштаб и закладки прокрутки каждой панели.
Разобранный PDF и размеры уже прочитанных страниц сохраняются над панелями:
переключение fullscreen не требует повторного получения или разбора файла.
Загрузка реальных метаданных обновляет геометрию, после чего восстанавливается
позиция. Старые демонстрационные страницы больше не используются для просмотра.

## Приватность и безопасность

Документы разбираются в браузере. Исходник отправляется только на свой backend
при явном запуске перевода; сторонним сервисам просмотра он не передаётся.
PDF worker, шрифты, CMap и WASM поставляются локально, без CDN.
JavaScript документов и интерактивные PDF-аннотации не подключены.

DOCX не вставляется в DOM как необработанный HTML. Разрешены только структурные
элементы и ограниченные атрибуты; скрипты, обработчики событий, встроенные стили,
iframe, активные ссылки и внешние изображения удаляются. Встроенные картинки
ограничены растровыми PNG/JPEG/GIF/WebP; SVG data URI не разрешены.
Внешний доступ Mammoth и встроенные style maps отключены.
Очистка HTML не делает любой документ безопасным для парсера: перед production
нужно поддерживать зависимости и отдельно проверять ресурсоёмкие файлы.

В текущем npm audit есть одна moderate-уязвимость sprintf-js, отражённая в трёх
пакетах цепочки Mammoth → argparse → sprintf-js. Она относится к CLI-парсеру
аргументов; argparse используется в bin/mammoth, а не в браузерном конвертере,
и не входит в собранный DOCX-chunk. На дату реализации исправленной версии
sprintf-js нет; предлагаемый npm downgrade Mammoth через audit fix --force
не применялся. Предупреждение не скрыто: проверить обновление/замену перед релизом.

## Ограничения первого этапа

- Старый бинарный DOC пока не отображается. Возможность перевода и скачивания
  не отключена; для просмотра нового исходника нужен PDF/DOCX.
- DOCX не имеет достоверного количества страниц в браузерной конвертации.
  Пагинация для него выключена, число страниц не выдумывается.
- Защищённые паролем PDF пока не открываются; показано соответствующее сообщение.
- Для PDF введён предел предпросмотра 2000 страниц. Это ограничение frontend,
  а не установленный лимит backend или подписки.
- Canvas отрисовывается лениво, но исходный файл/разобранные структуры находятся
  в памяти. DOCX-конвертация также не потоковая.
- После обновления страницы локальный исходник нужно выбрать снова.

## Проверки

```bash
npm test
npm run lint
npm run build
# При работающем dev server и установленном Google Chrome:
npm run test:viewer
# Для уже запущенной production-preview:
VIEWER_TEST_URL=http://127.0.0.1:3001 npm run test:viewer
```

Модульные тесты проверяют отмену загрузки, изоляцию книг, JWT-ротацию, состояния
API-ошибок, чтение файлов, блокировку HTML/JSON и очистку опасного DOCX-HTML.

Браузерный сценарий генерирует валидные PDF и DOCX в памяти, подставляет ответы
API только в изолированном Chrome и проверяет настоящие canvas/текст/таблицы/
изображения, количество страниц, навигацию, fullscreen, сохранение масштаба/
прокрутки, синхронизацию скрытой панели и повтор загрузки. Скриншоты лежат
в test-results (не включаются в Git). Это проверка viewer и интеграции frontend,
не проверка реального ML, доставки писем или production backend.

Ручная проверка: войти, выбрать свой PDF/DOCX, прокрутить и изменить масштаб,
переключить F/D/G, включить синхронизацию, запустить перевод и дождаться DONE.
Обновить страницу: перевод загрузится по восстановленному job_id; оригинал
нужно выбрать повторно. Проверить также повреждённый файл и неподдерживаемый DOC.
