# Восстановление интерфейса при навигации из полноэкранного режима

## Проявление ошибки

При включённом полноэкранном просмотре оригинала, перевода или обоих документов переход кнопкой браузера «Назад» на страницу настроек либо истории не восстанавливал боковую панель. Страница менялась, но общий макет оставался в режиме без интерфейса. Ошибка затрагивала клиентскую навигацию и не была связана с backend, JWT или загрузкой документов.

## Причина

Приложение построено как SPA с вложенными маршрутами React Router. Маршруты `/`, `/settings` и `/history` используют общий компонент `AppLayout`. При переходе между ними маршрутизатор заменяет содержимое `Outlet`, но сохраняет экземпляр родительского макета. Следовательно, значения его React-состояния не сбрасываются автоматически.

Полноэкранный просмотр управлялся двумя значениями в `AppLayout`: `expandedPanel` определяло показ только оригинала либо перевода, а `isDualPanelFullscreen` — показ обоих документов. На основе этих значений вычислялся `isFullscreenMode`. При его включении боковая панель и баннер подтверждения email не выводились, а CSS-класс `expandedMode` переключал сетку макета на одну колонку. В рабочей области также скрывалась панель инструментов.

До исправления эти значения сбрасывались при явном выходе из режима, например клавишей Escape. Обработки изменения маршрута не было. Переход «Назад» менял местоположение маршрутизатора, но не запускал обработчик кнопки выхода из полноэкранного просмотра. Сохранённые значения продолжали влиять на новый экран. Это несогласованность временного состояния представления с текущим маршрутом, а не неисправность самой кнопки браузера.

В данном приложении «полноэкранный режим» означает режим чтения, скрывающий интерфейс приложения средствами React и CSS. Это не браузерный Fullscreen API: браузерная адресная строка может оставаться видимой.

## Исправление

В `AppLayout` добавлена связь состояния просмотра с `location.key` — идентификатором записи навигации React Router. При смене этого ключа сбрасываются оба значения полноэкранного режима. Условное обновление собственного состояния компонента выполняется во время рендера: React повторяет рендер до фиксации дочернего интерфейса. Таким образом, устаревший режим не переносится на новый экран, а для сброса не нужен отдельный эффект после его отображения. Проверка изменения ключа исключает бесконечное обновление состояния.

Используется именно ключ записи, а не только `pathname`: история может содержать разные записи с одинаковым адресом `/`. Обработка охватывает переходы назад и вперёд (`POP`), обычные переходы (`PUSH`) и замену текущей записи (`REPLACE`). Возврат в рабочую область начинается в обычном режиме; режим чтения можно включить заново.

Дополнительно скрытие общего интерфейса допускается только для маршрута `/`. На страницах настроек и истории полноэкранный режим документов не должен влиять на макет. При этом сам `AppLayout` не перемонтируется целиком: выбранная книга и загруженный список документов сохраняются.

## Проверка

Добавлены восемь регрессионных сценариев в `src/test/App.interactions.test.tsx`: переходы назад и вперёд на настройки и историю для трёх режимов просмотра; переход между записями с одинаковым адресом; обычный переход и замена записи с сохранением выбранной книги. Проверяются возврат боковой панели и панели инструментов, показ обоих документов после возврата, повторное включение режима и выход клавишей Escape.

До изменения реализации шесть сценариев перехода на настройки и историю воспроизводили ошибку: заголовок новой страницы появлялся, а «Мои книги» отсутствовали. Проверки используют маршрутизатор с историей в памяти и DOM-среду jsdom; они не являются ручной проверкой кнопки реального браузера.

Для ручной проверки: открыть настройки, затем выбрать книгу в боковой панели; включить режим клавишей F, D либо G; нажать браузерную кнопку «Назад», затем «Вперёд». В настройках должна быть видна боковая панель, а после возврата к книге — боковая панель, toolbar и обе области документов.

## Вывод для проектирования

Временные состояния экрана должны иметь ограниченную область действия и согласовываться с навигацией. Сохранение общего макета полезно для данных пользователя, но не означает, что все визуальные режимы следует переносить между страницами. Регрессионные проверки истории навигации позволяют обнаружить ошибки, которые не проявляются при тестировании только внутренних кнопок приложения.
