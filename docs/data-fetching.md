# Загрузка данных: React Query

Данные с сервера читаются через TanStack Query (`@tanstack/react-query` 5).
Первым переведён раздел заметок; остальные хуки пока свои и переводятся по одному.

## Зачем

До перехода у каждого хука заметок были свои `AbortController`, состояния
«грузится / готово / ошибка» и ключ вида `email + запрос + revision`. Любая правка
увеличивала общий счётчик `revision` в `NotesContext`, и перечитывалось всё сразу:
заметки книги, список в колонке, боковая панель, граф. Из этого вытекали:

- **рывки и лишние перерисовки** — новый ответ всегда давал новые массивы, даже
  если ничего не изменилось, и поля книги перестраивались (так началась одна из
  причин рывка при сохранении заметки);
- **запросы при каждом переходе** — вернулся в книгу, и её заметки (список и
  каждая заметка с цитатами) читались заново, хотя только что были на экране;
- **рассинхрон** — сохранённую заметку показывали страница, панель и поля, и каждое
  место обновляло свою копию.

## Как устроено

- **Клиент** — `src/query/queryClient.ts`: данные свежие 30 секунд, при возврате на
  вкладку сами не перечитываются (заметки книги — десяток запросов), 4xx не
  повторяются, сеть и 5xx — один раз через 600 мс.
- **Провайдер** — `src/query/QueryProvider.tsx`, внутри `AuthProvider`. Клиент
  создаётся в компоненте, а не в модуле: у каждого монтирования приложения (и
  каждого теста) свой кэш. При выходе и смене аккаунта кэш очищается целиком.
- **Ключи** — `src/notes/noteQueries.ts` (`noteKeys`), все начинаются с
  `['notes', email]`:

  | Ключ | Что | Хук |
  | --- | --- | --- |
  | `list, запрос` | `GET /notes` по запросу | `useNotesList`, «Недавние» панели |
  | `section, {q, tag}` | список раздела страницами | `NotesProvider` (`useInfiniteQuery`) |
  | `search, {q, tag}` | поиск в боковой панели | `useNotesSidebar` |
  | `graph` | граф заметок, один на приложение | `NotesProvider` |
  | `note, id` | заметка | `useNote` |
  | `backlinks, id, название` | обратные ссылки | `useNote` |
  | `book, jobId` | цитаты и конспекты книги с текстом абзацев | `useBookNotes` |

- **После правки** — `notesChanged()` из `NotesContext` (`useNotesChanged`):
  списки, граф и заметки книги помечаются устаревшими, а те, что на экране,
  перечитываются. Ответ, который не изменился, не меняет ссылок на данные
  (structural sharing): поля, метки и списки не перерисовываются. Открытая
  заметка и её обратные ссылки только помечаются устаревшими: их может править
  открытый редактор, а свежую версию он получает из ответа сохранения.
- **Сохранённая заметка** сразу кладётся в кэш (`useRememberNote`,
  `useNote().applySaved`, `useBookNotes().upsertNote`): её новую версию видят все
  места, где она открыта, без запроса.
- **Заметка при открытии** показывается из кэша сразу и перечитывается в фоне
  (`staleTime: 0`), как раньше перечитывалась при каждом открытии.
- **Прежнее на экране, пока идёт новое**: смена поиска или фильтра оставляет
  прежний список (`keepPreviousData`); повтор после ошибки показывает загрузку, а
  не прежнюю ошибку.
- **Поиск в панели ждёт ввода** внутри запроса (250 мс, `pause` с отменой): каждая
  буква — новый ключ, а прежний запрос отменяется.
- **«Перешли по ссылке в книгу»** (`?note=`, `?summary=`) срабатывает по
  `isLoaded` — заметки прочитаны при этом открытии книги, а не взяты из старого кэша.

## Что осталось своим

SSE и опрос статусов перевода, общий файловый слот аккаунта (параллельный второй
запрос файла получает 429, поэтому текст книги грузится своим загрузчиком с
повтором, `documentText.ts`), конфликты версий и автосохранение заметок
(`NoteEditSession`), глоссарий, аккаунт и профиль.

## Замер

Сценарий в Chrome на демо-книге: книга → раздел «Заметки» → заметка → снова книга
→ снова заметка, переходы внутри приложения за 8 секунд. Запросы к заметкам:

| Шаг | До | После |
| --- | --- | --- |
| книга | 5 | 5 |
| раздел «Заметки» | 3 | 3 |
| заметка | 2 | 2 |
| снова книга | 5 | 0 |
| снова заметка | 3 | 2 (заметка показана сразу, перечитана в фоне) |
| всего | 18 | 12 |

Сохранение заметки на полях: новая метка и карточка появляются без перезагрузки,
страница не сдвигается.

Цена: основной бандл 470,41 → 478,25 КБ (gzip 142,23 → 144,32 КБ, +2,1 КБ).

## Тесты

Компоненты с данными рендерятся внутри `TestQueryProvider`
(`src/test/queryWrapper.tsx`): свой кэш на тест, без повторов после ошибки.
`src/test/noteQueries.test.tsx` проверяет сам кэш: перечитывание книги без смены
данных не меняет цитаты, правка перечитывает списки, но не открытую заметку,
сохранённая версия видна везде, смена аккаунта очищает кэш.

## Дальше

Следующим — глоссарий: термины сейчас лежат в двух местах (`useGlossaryTerms` и
`glossaryStore`) и обновляются руками в обоих. Затем аккаунт и профиль.

Новые разделы профиля уже на React Query: сеансы и статус двухэтапной
проверки (`account/securityQueries.ts`, ключи `['account', владелец, …]`), а
также письма в настройках (`account/notificationQueries.ts`, изменение сразу на
экране с откатом при ошибке).
Итог действия пишется в кэш сразу (`setQueryData`), список сеансов
перечитывается после действий, которые завершают чужие сеансы, и при возврате
на вкладку. Имя, фото, тариф и расход пока на прежних провайдерах.
