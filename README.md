# DocTranslate Frontend

Frontend сервиса перевода документов. Авторизация, профиль, загрузка, история,
статусы и скачивание подключены к Java backend. Панели показывают настоящие PDF
и DOCX. Оригинал берётся из выбранного локального файла, готовый перевод — из API.
Работа заметок ещё не реализована.

Профиль можно редактировать через меню пользователя → «Профиль».
В форме одно поле «Имя»; оно сохраняется через API. Остальные текстовые данные
профиля скрыты и сохраняются без изменений.
Email доступен только для чтения. Фото профиля можно загрузить, заменить и удалить;
аватар также отображается в меню. JPEG/PNG, до 2 МиБ. Внизу профиля — выход на
всех устройствах с подтверждением.
Подробности: [редактирование профиля](docs/profile-editing.md).

Раздел «Тариф и лимиты» получает текущую подписку и расход переводов с backend.
Остаток показан только в разделе тарифов и обновляется после загрузки и изменения
статуса задачи. Покупка и отмена подписки через интерфейс пока не подключены.
Подробности: [тарифы и лимиты](docs/plans-and-limits.md).

## Запуск

Для разработки используется Node.js 24 и npm. Версия Node указана в `.nvmrc`.
Backend запускается отдельно и не входит в этот репозиторий.

```bash
npm ci
cp .env.example .env
npm run dev
```

Если используете nvm, перед установкой зависимостей выполните `nvm install`
и `nvm use` в папке проекта. Зависимости устанавливаются по `package-lock.json`,
который хранится в Git.

Приложение доступно по адресу `http://localhost:3000/`. Vite настроен с
`strictPort`, поэтому при занятом порте 3000 запуск завершится понятной ошибкой,
а не переключится на другой порт.

## Работа с Git

В репозитории хранится только frontend: исходники, тесты, документация,
конфигурация и lock-файл. `node_modules`, сборка `dist`, скриншоты тестов,
локальные `.env` и служебные файлы macOS исключены через `.gitignore`.
Для настроек окружения используется безопасный шаблон `.env.example`.
Пароли, токены и приватные ключи не коммитьте. Значения `VITE_*` попадают
в клиентский код, поэтому секретов в них быть не должно.

Обычный цикл сохранения изменений:

```bash
git status
git add src
git diff --cached
git commit -m "Describe the frontend change"
git push
```

Если менялись другие папки или конфигурация, добавьте их явно через `git add`.
Перед отправкой изменений выполните проверки из следующего раздела.

## Проверки

```bash
npm run lint
npm test
npm run build
```

Тесты проверяют API, авторизацию и продление сессии, одновременные 401,
восстановление после перезагрузки, координацию вкладок, выбор документов,
прокрутку, масштабирование, fullscreen, маршруты, загрузку файлов для просмотра
и очистку HTML документов.

Браузерные проверки отображения документов, тарифов и профиля в Chrome:

```bash
# Предварительно запустить npm run dev; нужен установленный Google Chrome.
npm run test:viewer
npm run test:account
npm run test:profile
```

Проверки используют тестовые данные и перехватывают API в изолированном браузере.
Проверка viewer отображает настоящие PDF/DOCX-файлы; проверки не изменяют данные
на backend и не проверяют ML-перевод. Подробнее:
[просмотр документов](docs/real-document-viewer.md).

## Backend contract

- Локальный backend: `http://localhost:8080`.
- Browser API base: `/api`.
- В режиме разработки Vite проксирует `/api` в backend, поэтому включать CORS
  для `localhost:3000` не требуется.
- Endpoints: `src/api/endpoints.ts`.
- DTO: `src/api/contracts`.
- HTTP-клиент и единая обработка ошибок: `src/api/client.ts`.
- Доменные API-модули: `src/api/auth.ts`, `src/api/documents.ts`,
  `src/api/translations.ts`, `src/api/account.ts`, `src/api/profile.ts`.
- Полное описание JWT, ошибок, статусов и ограничений API:
  `docs/backend-api-contract.md`.

## Маршруты

- `/` — рабочая область; список и статусы с backend, просмотр PDF/DOCX
- `/login`, `/register` — вход и регистрация
- `/history` — история задач с backend
- `/settings` — тема и язык интерфейса
- `/plans` — текущий тариф, подписка, расход и остаток переводов с backend
- `/profile` — получение и редактирование профиля через backend
- `/verify-email`, `/forgot-password`, `/reset-password` — подтверждение и восстановление

Выбор файла создаёт локальный черновик; кнопка перевода отправляет его на backend.
Оригинал доступен для просмотра сразу. После завершения перевода правая панель
получает готовый файл автоматически. Backend пока не позволяет скачать оригинал:
после перезагрузки его можно выбрать повторно в левой панели просмотра, без
повторного запуска перевода. PDF отображается постранично; DOCX — как адаптированный
текст с таблицами и изображениями, без точной Word-вёрстки. Старый формат DOC
можно отправлять и скачивать, но просмотр в браузере для него пока недоступен.

Кнопка «Скачать» получает готовый результат по job_id и запускает сохранение
файла в браузере. Пока идёт запрос, повторные нажатия заблокированы; смена книги
или выход отменяет запрос. Для неготовых/ошибочных задач кнопка неактивна.

Ожидание перевода ограничено: если статус и прогресс не меняются 2 минуты,
автопроверка приостанавливается. Кнопка «Проверить статус» возобновляет проверку
того же job_id, без повторной загрузки. Это не отмена задачи на сервере.
Отдельный GET-запрос проверки имеет таймаут 10 секунд. Подробности:
[ограничение ожидания](docs/translation-waiting-timeout.md).

## Продление сессии

Access token хранится только в памяти, refresh token — в HttpOnly cookie backend.
При перезагрузке frontend восстанавливает вход через `POST /api/auth/refresh`.
JWT обновляется за минуту до истечения; защищённый запрос после 401 повторяется
один раз. Параллельные запросы ждут одну promise; вкладки координируются через
Web Locks и BroadcastChannel. Нужен современный браузер на localhost или HTTPS.
В localStorage хранится только несекретный маркер состояния, не токены.
Старый JWT из sessionStorage однократно переносится в память и удаляется.

Выход вызывает `POST /api/auth/logout` и отзывает текущую серверную сессию.
«Выйти на всех устройствах» в профиле вызывает `POST /api/auth/logout-all`
с JWT, отзывает сессии аккаунта и возвращает на страницу входа.
При потере ответа refresh не повторяется автоматически: интерфейс предлагает
войти заново, чтобы не нарушить строгую ротацию cookie.

Нужен backend с refresh API (контракт от 2026-10-07). Обновлённые исходники
не означают, что запущенный Docker-образ уже обновлён. Если ответ login не
содержит `Set-Cookie: translatelab_refresh=...`, необходимо пересобрать контейнер
backend по инструкции команды; frontend не может заменить серверный refresh.
